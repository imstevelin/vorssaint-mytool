# 原生顯示器按鍵與動態島音量

2026-10-17 實作。

## 使用行為

- 顯示器控制、原生亮度鍵及亮度 OSD 預設開啟；既有安裝也會一次性採用新預設。之後使用者自行關閉的選擇會保留，不在每次啟動覆寫。
- 亮度鍵調整游標所在螢幕；HiDPI 虛擬桌面映射回實體螢幕。內建螢幕及系統支援的路線保留原生處理。
- 音量／靜音鍵跟隨系統目前的音訊輸出。CoreAudio 可控制時優先使用 CoreAudio；HDMI／DisplayPort 喇叭缺少原生音量時自動使用 DDC。
- 不需要選擇音訊綁定。設定頁的「自動配對（預設）」即可使用；手動綁定仍可作為特殊硬體的覆寫。
- 多螢幕先以目前顯示音訊的名稱唯一配對；只有一台實體外接螢幕時可自動選它。名稱重複、無法唯一配對或該台不支援音量時，不把指令轉給其他螢幕。藍牙、USB 音訊不因旁邊只有一台螢幕而被錯誤配對。
- 動態島音量卡片、播放中的音量控制及混音器主音量統一使用 `SystemOutputControl`，因此 DDC 螢幕喇叭不再被誤判為不可用。滑桿、百分比及靜音狀態與音量鍵共用同一台裝置。

macOS 的輔助使用授權仍是全域按鍵攔截的系統要求。本機已授權，無需增加 APP 內設定；首次使用尚未授權的 Mac，仍需完成該系統授權。

## 驗證

- 本機系統預設音訊輸出為 PA328QV，CoreAudio 回報 DisplayPort／HDMI 類型，無需手動綁定。
- 安裝後從動態島混音器確認：輸出裝置 PA328QV、音量滑桿、24% 讀值及可用的靜音按鈕均已顯示，取代原本的「不可用」。24% 是當時裝置讀值，不是寫死的預設。
- 系統 `CGGetEventTapList` 確認正式 APP 已註冊兩個啟用中的原生媒體鍵事件攔截器。
- 自動化測試直接編譯產品的媒體鍵回呼，驗證音量增加、降低、靜音、按下／放開配對、失敗後標記回退及原生音訊放行；無需實際向系統發送按鍵。
- 共用音量控制測試包含 DDC 讀值、滑桿寫入與解除靜音、原生輸出優先、輸出消失及寫入失敗。配對測試包含單／多螢幕、同名歧義、無 DDC 音量的顯示器、手動覆寫及 Bluetooth 排除。
- 預設與遷移測試包含全新安裝預設開啟、舊安裝一次性開啟及後續明確關閉不被覆寫。

本輪的原生按鍵路由由產品回呼測試與執行中事件攔截器證據驗證；電腦操作工具不支援模擬 macOS 音量硬體鍵，沒有將該工具的按鍵模擬宣稱為實體鍵盤測試。DDC 硬體讀寫證據另見 [DISPLAY_INTEGRATION_VERIFICATION.md](DISPLAY_INTEGRATION_VERIFICATION.md)。

## 快速連按音量鍵修正（2026-10-17）

先前 DDC 音量通知在寫入及讀回完成後才發出；連按時舊請求的完成通知被新版略過，靈動島便停在舊值直到最後一次讀回。

現在每次請求先發布預期音量及靈動島通知，DDC 繼續在背景執行。開始硬體交易前會略過已被取代的排隊寫入；已在執行中的交易可完成，但不覆蓋較新的顯示值，也不觸發過期的原生音量回退。成功讀回不重播通知；失敗則修正為最近確認的值。從靜音調整音量時，解除靜音意圖也立即反映。

`DisplayAudioBurstTests` 直接抽取產品的請求、步進及 OSD 方法，使用手動推進的佇列及 DDC 替身，驗證五次快速連按在硬體回應前依次顯示 26、32、38、44、50%，且硬體只收到尚未執行請求的最後目標。另測試舊讀回晚到、過期寫入失敗、回復最近確認值及解除靜音。這是產品方法的延遲回歸測試，並非實體鍵盤連按實測。

本輪驗證：`display-restoration` 155 項與 `notch` 71,716 項均通過（共 71,871 項）。正式版已重新建置、安裝至 `/Applications/實用小工具.app` 並通過深層嚴格簽章驗證；重新啟動後，靈動島混音器仍可辨識 PA328QV 並提供音量滑桿與靜音控制。
